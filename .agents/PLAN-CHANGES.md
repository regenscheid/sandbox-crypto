# Plan changes

Dated log of changes to the plan, decisions and conventions ([conventions](CONVENTIONS.md)). Newest first.

## 2026-10-10

- **Policy middleware service (D70, proposed;** [policy middleware](../docs/POLICY-MIDDLEWARE.md)**).** `packages/policy-middleware` implements OpenShell v0.1.3's supervisor middleware contract (vendored, Apache-2.0) and decides each request with the library. It decides under the revision the orchestrator binds each sandbox to, and denies requests from a sandbox still running an older compiled policy. It verifies the gateway's extension tokens and accepts an evaluation only from the requesting sandbox's supervisor. Because it runs before credential injection, every request of a project with providers counts as credentialed. It denies WebSocket upgrades at preflight, checks that git fetch bodies are upload-pack requests, and records escalations, alerts and monitor findings. The OpenShell v0.1.3 binaries are installed on babbage for the end-to-end checks.
- **Tier 1 licenses add MIT-0** ([licensing](../docs/LICENSING.md)). cryptography, which verifies the middleware's Ed25519 tokens, requires cffi (MIT-0: MIT without the attribution condition). CI now also checks that the generated protobuf code matches the vendored contracts.
- **OpenShell compiler and policy middleware (D69; direction confirmed by the user, details proposed).** OpenShell cannot express the policy exactly, so research sandboxes' traffic goes through OpenShell's own proxy, and the platform's policy middleware decides each admitted request with the library. OpenShell keeps TLS, credential injection (D57 unchanged) and logging. The compiler emits admission endpoints and attaches the middleware, and re-enforces MCP tool rules in the MCP proxy's sandbox. The separate egress proxy (D44) is dropped for HTTP and git, and package indexes are reachable only through the package mirror. A first design, a TCP fence around our own egress proxy, was replaced after the user asked whether OpenShell could keep handling the traffic. An independent review of the compiler's MCP part found 12 issues, now fixed: root-path selectors, bare-prefix admission, ignored `revision`, unreported `worker_tools` looseness, shared endpoints, OpenShell's tool-name rules, URL forms, inaccurate findings and YAML 1.2 quoting. The issues that concerned the dropped egress-proxy fence led to the package-index reservation.
- **Fifth review round.** It confirmed the round-4 fixes. One gap remained: a `#` inside a quoted value made the live settings after it read like a comment (`revision: "2025-11-25 # pinned", tools: {...}`). A value containing `#` must now end its line.
- **Fourth review round.** It confirmed the round-3 fixes and beat the new layout check three ways: a multi-line quoted string swallowed lines that looked like live settings, a stray quote desynchronized the hand-written scanner, and blank-looking characters padded a line. The check now takes positions from PyYAML's own scanner, every value must fit on one line, settings must be ASCII (comments may use other scripts), and tabs and blank-looking characters are rejected.
- **Third review round.** It confirmed 6 of the 8 round-2 fixes and found 5 more issues, now fixed. Policy lines are at most 160 columns wide, have no runs of blanks except before comments, and contain no unusual whitespace, so that content cannot hide off-screen. A server declared by IP address is reserved under any name that resolves to it. Windows best-fit path characters and `::$` are ambiguous. Resource numbers are finite and unquoted, and MCP server URLs reject whitespace and control characters.
- **Second review round.** A re-review confirmed 9 of the 12 fixes and found 8 more issues, now fixed. A git POST needs a body and exactly git's content type, since the agent chooses the header. The evaluator takes the addresses the proxy resolved and checks them against the floor, admin hosts and ceiling deny lists in every address form. A declared MCP server's whole host is reserved for the MCP proxy. Policy files may not use backslash escapes, lines over 300 characters or keys without values, and quoted values are not converted. The example allows crypto-research-mcp tools by exact name only, so unknown and compound names ask first. PR #3 merged before the first round of fixes, so both rounds land in the follow-up PR.
- **Policy hardening after an adversarial review** ([policy](../docs/POLICY.md), `test_review_regressions.py`). The review found 12 bypasses. Three affected the shipped example: `*search*` matched every crypto-research-mcp tool through the portal prefix, so servers now declare a `tool_prefix` and the example's patterns are anchored; any POST ending in `/git-upload-pack` counted as a git fetch, so git POSTs now need git's content type; and lowercase methods counted as reads. Also fixed: IPv6 spellings of IPv4 addresses and zone IDs, which slipped past exact host lists; a strict YAML dialect, so a file reads as it is enforced; ceiling keys without values; double encoding and trailing-dot paths; ties that dropped limits; `fec0::/10`; more metadata endpoints; non-library exceptions; and direct egress to declared MCP endpoints. Bodies on GET, protocol upgrades and zero memory limits are now rejected.
- **OpenShell policy facts** ([investigation](docs/agent-reports/openshell-policy-v0.1.3.md)). OpenShell v0.1.3 cannot express "any host" as an endpoint, and its `upstreamProxy` only chains TLS tunnels, so rules for `*` are enforced by the project egress proxy rather than through `upstreamProxy` as POLICY.md had proposed. OpenShell defaults endpoints to audit mode and has no rule specificity (allows union, any deny wins); the mapping in POLICY.md now says how the compiler handles both. Because OpenShell strips `;` path parameters and servers disagree on them, the classifier now treats them as ambiguous.
- **Policy evaluation details (D68, proposed).** Writing the evaluator in `packages/policy` turned D62's prose into precise rules ([policy](../docs/POLICY.md)). Three gaps needed a decision: the example's `large-egress` alert could never fire under most-specific-wins, so threshold alerts move to a new `monitors` section; `*search*` allowed crypto-research-mcp's `firecrawl_search_feedback`, which submits feedback, so tool patterns now resolve exact names first and otherwise take the most restrictive list; and `on_timeout: allow` "for alert-class rules" had no meaning, so the policy-wide value must be `deny` and only read-only rules may time out to an alert. New safety rules: wildcards and defaults never grant non-public destinations, ambiguous requests are denied, and the hard floor also covers loopback, unspecified and Kubernetes API addresses.
- **Example policy.** `large-egress` moved to `monitors`. The crypto-research-mcp tool lists were rewritten against the server's 78 tools, classified from their own descriptions; a test fixture pins each tool's outcome. Per-call billed searches and cache-filling document reads stay allowed by choice; feedback, crawl, agent, scrape, parse, interact, monitor-changing and refresh tools ask first; portal configuration is denied.
- **Tier 1 licenses add PSF-2.0** ([licensing](../docs/LICENSING.md)). pydantic requires typing-extensions (PSF-2.0, permissive and GPL-compatible). CI now checks the licenses of all installed distributions.
- **Conventions adopted** ([CONVENTIONS.md](CONVENTIONS.md)), carried over from the paused `impl/p-policy-engine` branch. Pyright strict applies to `packages/*/src` as the conventions state; tests use standard mode.
- **Plan snapshots tagged.** The signed tags `plan-03-pre-review` (`cb89015`) and `plan-04-reviewed` (`9e4ae25`) are on GitHub, as the [analysis archive](docs/README.md) already described.
