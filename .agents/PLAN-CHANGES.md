# Plan changes

Dated log of changes to the plan, decisions and conventions ([conventions](CONVENTIONS.md)). Newest first.

## 2026-10-11

- **W1 started** ([execution tools spec](../docs/specs/tools.md), [worker](../docs/WORKER.md)).
  - New workspace members: `contracts` (library), `worker` (the trusted worker service, plus an executor that runs inside sandboxes) and `orchestrator` (the harness).
  - Proposed in the spec, for the user to review: shell calls keep no state between calls, and a cell exception is its own error kind (`exception`).
  - The first slice uses its own code for the tool loop, an aiohttp client for LiteLLM's OpenAI-compatible endpoint (no SDK), and jupyter_client/ipykernel for kernels. Evaluating OpenCode and OpenScience Desktop for reuse is still open (W0).
  - The license check now accepts an SPDX identifier in the legacy `License` field (psutil).
- **Lab 3 on babbage** ([lab report](docs/agent-reports/babbage-openshell-lab-3-2026-10-11.md)). The compiled credential bindings loaded with an endpointless provider and behaved as designed, including for a bound host that rules also name. OpenShell's substitution of credentials into plain HTTP on port 443 was seen at runtime. The bug description now says so; it remains a residual risk.
- **Upstream bug descriptions** ([conventions](CONVENTIONS.md)). `.agents/upstream/` holds descriptions of bugs found in upstream projects. The user chose to keep the two OpenShell v0.1.3 bugs there rather than file them:
  - provider credentials substituted into plain HTTP and sent unencrypted;
  - a host with two trailing dots selecting no middleware.

## 2026-10-10

- **Provider credentials bound by the compiled policy (D57 amended, chosen by the user).** Lab 2 showed that a provider whose profile names a host cannot sit beside the compiled policy's host-less endpoint. The user chose the arrangement where the project policy names the hosts each provider's credential may reach (`credentials.providers[].hosts`, required, exact names only), over profiles that repeat the compiler's address ranges.
  - The compiler binds each credential with `credential_binding` on port 443 and path `/**`. Other endpoints for the host leave port 443 out, and in a closed policy only hosts its rules name are bound.
  - Providers use profiles without endpoints; an example is in `examples/openshell/profiles/`.
  - The middleware counts only requests to those hosts as credentialed, so `on_timeout: allow` rules no longer need `allow_credentialed` for other hosts. This relies on the orchestrator attaching exactly the listed providers (backlog).
  - An adversarial review found nothing critical. Its main finding: OpenShell substitutes a bound credential into plain HTTP sent to port 443 and forwards it unencrypted. The middleware now refuses such requests where OpenShell reports them as plain HTTP (`credential_unencrypted`). Through a tunnel the request is labelled `https`, so that route is a residual risk and a possible upstream report (the user's call).
- **Lab 2 on babbage** ([lab report](docs/agent-reports/babbage-openshell-lab-2-2026-10-10.md)).
  - Real clients installed through the middleware and the package cache in a sandbox.
  - Cargo needs `http.multiplexing = false` while the cache is plain HTTP. The client configuration now says so.
  - Lockfiles written in a sandbox name the cache (backlog).
  - OpenShell refuses overlapping endpoints whose address ranges differ, so a provider whose profile names a host cannot be attached to a research sandbox as it stands. Two arrangements work; the user will choose.
  - The MCP proxy's policy loaded and its rules held.
  - The v0.1.3 prover reports policies with middleware or MCP endpoints as unsupported. The threat model (A3) and monitoring no longer rely on it for those policies.
- **Package cache review.** An independent review of the cache found no way to poison it, get a file past its digest check, or make it fetch from anything but its configured registries. Across about 300,000 generated paths, the cache and the policy classifier never disagreed about a path's ecosystem, kind or package. It did find availability problems that let one sandbox degrade the shared cache for every project:
  - downloads repeated for wrong digests;
  - a shared connection pool with no wait limit;
  - unbounded rewrites of very large index documents;
  - slow readers holding connections;
  - "not found" entries growing without limit;
  - redirects to internal hosts.
  It also found two bugs: the npm lockfile route was missing from the adapter, and PyPI keys ignored the digest. These are fixed in the cache PR. Per-sandbox rate limits need the middleware to identify the sandbox to the cache, and are on the backlog with the cooling-off period.
- **Package cache service built** ([package cache](../docs/PACKAGE-CACHE.md), D71). It has a core (aiohttp server, content-addressed store with LRU eviction, verified streaming fetches, revalidation, a rate limit) and an adapter for each of PyPI, conda, Cargo, Go and npm. Four agents built it in parallel against a written contract. Along the way they found two gaps, now fixed: lockfile installs (npm, pnpm and yarn fetch `<name>/-/<file>.tgz`) and the real conda shard path. Real pip, uv, mamba, cargo, go and npm clients install through it.
- **Package policy review.** An adversarial review of the package policy found one critical problem, now fixed. OpenShell selects middleware by host alone, so excluding the raw MCP proxy's host also took the package cache out of the middleware whenever both ran on `host.openshell.internal`, the single-host setup the docs recommended. The services are now inspected endpoints, and nothing is excluded. Also fixed:
  - the pool ceiling applies to package registries;
  - registry aliases and mirrors are on the floor;
  - the compiler stops admitting hosts the library always denies;
  - file names are tied to the package in the path;
  - Go module requests are also decided as reads of the module's origin host, which the Go proxy contacts;
  - real client paths the classifier refused (conda shards, PyPI epochs, legacy npm names, lockfile tarballs) are now accepted;
  - service hosts are normalized, and other ports on them are denied.
  An OpenShell issue, where a host ending in two dots selects no middleware, is recorded for an upstream report.
- **Package cache instead of a mirror (D71, direction confirmed by the user).** The user pointed out that the cache cannot store everything, and that crypto code is often C, C++, Rust, Go or npm. Packages now come through a pull-through cache for PyPI, conda, crates.io, Go modules and npm; opam and Hackage follow, for EasyCrypt and similar tools. The cache keeps only what sandboxes use, up to a size cap, and verifies files against published digests. The policy middleware decides every request to it with the `packages` section: index lookups are allowed unless the ecosystem is denied, and package files take its action. The cache is therefore an inspected endpoint behind the middleware, no longer a raw TCP service. The registries' hosts are on the floor for generic HTTP. Writing the compiler side exposed a floor gap: `host.openshell.internal`, OpenShell's name for the gateway host, was missing, so a project rule could have reached every service on that host. It is on the floor now, and the compiler accepts it only as an operator-chosen platform-service host.
- **`allow_credentialed` (D68 extended, requested by the user).** A read-only rule with `on_timeout: allow` can also set `allow_credentialed: true`, so that a request that may carry a provider credential also proceeds as an alert when nobody answers. Without it, credentialed requests are still denied on timeout. The user asked for this endpoint by endpoint, because the policy middleware counts every request of a project with providers as credentialed. URL limits still deny on timeout, and tied rules must all opt in.
- **Admission names hosts; on-demand admission planned (D69 amended, chosen by the user).** On babbage, the policy middleware worked end to end against a real OpenShell gateway ([lab report](docs/agent-reports/babbage-openshell-lab-2026-10-10.md)). The lab also showed that a VM sandbox resolves only host names an endpoint names, so the host-less endpoint admitted only addresses, and `*` rules could reach no website. Of the options (name hosts now and admit others on demand later; name hosts only; DNS wildcards, which OpenShell refuses over a top-level domain and which open a DNS exfiltration channel), the user chose the first. The compiler now names every public host the policy mentions and compiles `*.suffix` to `**.suffix`. The middleware gained a `store` command, because the gateway validates a compiled policy before the sandbox exists.
- **Policy middleware service (D70, proposed;** [policy middleware](../docs/POLICY-MIDDLEWARE.md)**).** `packages/policy-middleware` implements OpenShell v0.1.3's supervisor middleware contract (vendored, Apache-2.0) and decides each request with the library. It decides under the revision the orchestrator binds each sandbox to, and denies requests from a sandbox still running an older compiled policy. It verifies the gateway's extension tokens and accepts an evaluation only from the requesting sandbox's supervisor. Because it runs before credential injection, every request of a project with providers counts as credentialed. It denies WebSocket upgrades at preflight, checks that git fetch bodies are upload-pack requests, and records escalations, alerts and monitor findings. The OpenShell v0.1.3 binaries are installed on babbage for the end-to-end checks.
- **Tier 1 licenses add MIT-0** ([licensing](../docs/LICENSING.md)). cryptography, which verifies the middleware's Ed25519 tokens, requires cffi (MIT-0: MIT without the attribution condition). CI now also checks that the generated protobuf code matches the vendored contracts.
- **OpenShell compiler and policy middleware (D69; direction confirmed by the user, details proposed).** OpenShell cannot express the policy exactly, so research sandboxes' traffic goes through OpenShell's own proxy, and the platform's policy middleware decides each admitted request with the library. OpenShell keeps TLS, credential injection (D57 unchanged) and logging. The compiler emits admission endpoints and attaches the middleware, and re-enforces MCP tool rules in the MCP proxy's sandbox. The separate egress proxy (D44) is dropped for HTTP and git, and package indexes are reachable only through the package mirror. A first design, a TCP fence around our own egress proxy, was replaced after the user asked whether OpenShell could keep handling the traffic. An independent review of the compiler's MCP part found 12 issues, now fixed: root-path selectors, bare-prefix admission, ignored `revision`, unreported `worker_tools` looseness, shared endpoints, OpenShell's tool-name rules, URL forms, inaccurate findings and YAML 1.2 quoting. The issues that concerned the dropped egress-proxy fence led to the package-index reservation.
- **Fifth review round.** It confirmed the round-4 fixes. One gap remained: a `#` inside a quoted value made the live settings after it read like a comment (`revision: "2025-11-25 # pinned", tools: {...}`). A value containing `#` must now end its line.
- **Fourth review round.** It confirmed the round-3 fixes and beat the new layout check three ways: a multi-line quoted string swallowed lines that looked like live settings, a stray quote desynchronized the hand-written scanner, and blank-looking characters padded a line. The check now takes positions from PyYAML's own scanner, every value must fit on one line, settings must be ASCII (comments may use other scripts), and tabs and blank-looking characters are rejected.
- **Third review round.** It confirmed 6 of the 8 round-2 fixes and found 5 more issues, now fixed. Policy lines are at most 160 columns wide, have no runs of blanks except before comments, and contain no unusual whitespace, so that content cannot hide off-screen. A server declared by IP address is reserved under any name that resolves to it. Windows best-fit path characters and `::$` are ambiguous. Resource numbers are finite and unquoted, and MCP server URLs reject whitespace and control characters.
- **Second review round.** A re-review confirmed 9 of the 12 fixes and found 8 more issues, now fixed. A git POST needs a body and exactly git's content type, since the agent chooses the header. The evaluator takes the addresses the proxy resolved and checks them against the floor, admin hosts and ceiling deny lists in every address form. A declared MCP server's whole host is reserved for the MCP proxy. Policy files may not use backslash escapes, lines over 300 characters or keys without values, and quoted values are not converted. The example allows crypto-research-mcp tools by exact name only, so unknown and compound names ask first. PR #3 merged before the first round of fixes, so both rounds land in the follow-up PR.
- **Policy hardening after an adversarial review** ([policy](../docs/POLICY.md), `test_review_regressions.py`). The review found 12 bypasses. Three affected the shipped example: `*search*` matched every crypto-research-mcp tool through the portal prefix, so servers now declare a `tool_prefix` and the example's patterns are anchored; any POST ending in `/git-upload-pack` counted as a git fetch, so git POSTs now need git's content type; and lowercase methods counted as reads. Also fixed: IPv6 spellings of IPv4 addresses and zone IDs, which slipped past exact host lists; a strict YAML dialect, so a file reads as it is enforced; ceiling keys without values; double encoding and trailing-dot paths; ties that dropped limits; `fec0::/10`; more metadata endpoints; non-library exceptions; and direct egress to declared MCP endpoints. Bodies on GET, protocol upgrades and zero memory limits are now rejected.
- **OpenShell policy facts** ([investigation](docs/agent-reports/openshell-policy-v0.1.3.md)). OpenShell v0.1.3 cannot express "any host" as an endpoint, and its `upstreamProxy` only chains TLS tunnels, so rules for `*` are enforced by the project egress proxy rather than through `upstreamProxy` as POLICY.md had proposed. OpenShell defaults endpoints to audit mode and has no rule specificity (allows union, any deny wins); the mapping in POLICY.md now says how the compiler handles both. Because OpenShell strips `;` path parameters and servers disagree on them, the classifier now treats them as ambiguous.
- **Policy evaluation details (D68, proposed).** Writing the evaluator in `packages/policy` turned D62's prose into precise rules ([policy](../docs/POLICY.md)). Three gaps needed a decision: the example's `large-egress` alert could never fire under most-specific-wins, so threshold alerts move to a new `monitors` section; `*search*` allowed crypto-research-mcp's `firecrawl_search_feedback`, which submits feedback, so tool patterns now resolve exact names first and otherwise take the most restrictive list; and `on_timeout: allow` "for alert-class rules" had no meaning, so the policy-wide value must be `deny` and only read-only rules may time out to an alert. New safety rules: wildcards and defaults never grant non-public destinations, ambiguous requests are denied, and the hard floor also covers loopback, unspecified and Kubernetes API addresses.
- **Example policy.** `large-egress` moved to `monitors`. The crypto-research-mcp tool lists were rewritten against the server's 78 tools, classified from their own descriptions; a test fixture pins each tool's outcome. Per-call billed searches and cache-filling document reads stay allowed by choice; feedback, crawl, agent, scrape, parse, interact, monitor-changing and refresh tools ask first; portal configuration is denied.
- **Tier 1 licenses add PSF-2.0** ([licensing](../docs/LICENSING.md)). pydantic requires typing-extensions (PSF-2.0, permissive and GPL-compatible). CI now checks the licenses of all installed distributions.
- **Conventions adopted** ([CONVENTIONS.md](CONVENTIONS.md)), carried over from the paused `impl/p-policy-engine` branch. Pyright strict applies to `packages/*/src` as the conventions state; tests use standard mode.
- **Plan snapshots tagged.** The signed tags `plan-03-pre-review` (`cb89015`) and `plan-04-reviewed` (`9e4ae25`) are on GitHub, as the [analysis archive](docs/README.md) already described.
