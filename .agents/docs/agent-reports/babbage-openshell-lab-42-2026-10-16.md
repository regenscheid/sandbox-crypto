## Bugs

- **B1, high: skill embeddings never work with the gateway.** `skills/embeddings.py` reads an answer with one `response.content.read(MAX_ANSWER_BYTES + 1)`, which returns only the bytes that have arrived, so a large answer is cut and `json.loads` fails. Every import, every background build (retried after 60, 120, 240 and 480 s) and every run failed with "the gateway's answer is not embeddings (JSONDecodeError)". No vector was stored; search and discovery compared by words throughout, and 12 charged calls bought nothing. Reproduction: a loopback `/embeddings` that sends a valid answer of 64 vectors of 1,536 in 64 KiB writes gives the same error, while one vector passes. `model.py`'s `_read_limited` reads to the end with a limit.
- **B2, high: plan changes are left out of the review's actions.** `plan_create`, `plan_activate`, `plan_progress`, `plan_finish` and `track_progress` have the effect class `plan`, and `consistency/actions.py` lists only `effect`. Run 3 recorded three steps and finished the plan, and said so. Its review raised `fail`: "the pinned current plan still has status active and those three steps pending". Two more fails followed, and a confirmation in run 5 raised a fourth. Run 3's 794,458 input tokens went mostly to answering them. Reproduction: a run that records progress, finishes its plan and says so.
- **B3, high: a delegated run's computation never reaches the review.** `consistency/delegated.py` brings in a delegated run's action records ("sage … execution exe-166b… (succeeded)") and its outcome, but not the execution items with their output, which a main run's own executions get. Run 5's task printed …7031 from Sage and returned a summary saying the factor ends in …7033. The terminal review took that summary, as the run relayed it, for "the assistant's own checked verdict" and failed the document's …7031, the right value. Two confirmations then confirmed patches that made the document wrong (rev-0353 passed; rev-8250: "document revision 4 now agrees internally"). The document now gives a wrong factor, and its findings read "confirmed fixed". Reproduction: a delegated computation whose summary misstates its output.
- **B4, medium, reported: a run's last text replaces its answer.** A run's `final_text`, which the chat's later history uses, is its last text. Run 3's answer ("The plan is finished … Its output was: twist-done") is followed in its record and in later runs' history by "I checked the pinned evidence and responded to the finding…". Run 2's skills report became a plan statement after the hold. The chat shows every text.
- **B5, low, reported: a terminal review of the closing answer alone cannot check it.** Run 1's terminal review covered only the answer (window 83 to 83), whose `document_create` was in the checkpoint's window. It ended inconclusive: "There is no document revision or other record to verify the claimed creation".
- **B6, low: the correction for an empty `obstacle` asks for one.** A complete task that sent `"obstacle": ""` was told "obstacle: Value error, a text of 1 to 1000 characters, not 0". It wrote one, and the second answer was refused: "a blocked task names its obstacle, and only a blocked one does". The task kept no result.
- **B7, low: the launcher prints the gateway's HTML error page.** "the pass's call failed: the model gateway returned 524: <!DOCTYPE html> <!--[if lt IE 7]> …", 300 characters of Cloudflare's page in the line and the log.
- **B8, low: the config script sets no skill packs.** `launcher_config.py` has no option for `[skills]`, its models or a project's `skills`; the lab edited the config, as lab 41 did for the profile.

## Observations, not fixed

- **The pass on the update covered 150 of 162 skills in 4 topics**, with 4 entry skills, but no short description. The index then shows the entry skills' own descriptions cut at a word.
- **The pass failed once with the gateway's 524** (a Cloudflare timeout). `up` does not try it again; `sandbox-science skills update` did, on the same import.
- **`search` does not tell the model it ran on words alone.** Its record says `scoring: lexical` and why, but the answer does not. The notice's framing says the skills "matched this message by its words or its meaning" when only words were used.
- **The chat shows "skills: no state recorded"** for every `skills` call, rather than what loaded.
- **A run started by a comment gets no discovery** for the comment's text: its task is the stand-in, and the comment comes as a `requests` notice.
- **Review findings keep runs going after their answers.** Runs 3, 5 and 6 spent 1,595,921 input tokens in 46 calls on findings, every one of them B2's false findings or built on B3's wrong summary.
- **The first run waited 72 s** between its request and its start, while the research sandbox started.

## Whether what merged works

Mostly, on words. The launcher imports a pack once, pins it, fetches nothing on the next `up`, notes a changed ref, and reports what an update added and changed. The pass's checks drop bad items with reasons, and costs show under their roles. Runs get an index within budget, with entry skills and topics. They get a `skills` tool whose loads carry both hashes, whose reads stay in the set, and whose cap holds. Start loads are recorded, built-ins follow the run's role, and discovery notices stay within five, never repeat, and skip "Thanks!". Meaning does not work at all: B1 breaks every embedding, so search and discovery fall back to words. Lab 41's fixes hold where exercised (B2, B5, B7, B8, and B1's refusal and confirmation). The review has two new gaps: plan changes are not actions (B2), and a delegated run's output is not evidence (B3). Together they produced false `fail` findings and a confirmed wrong fix, and most of the lab's tokens.
