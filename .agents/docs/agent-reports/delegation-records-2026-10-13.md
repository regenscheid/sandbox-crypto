No delegated child is launched by this increment. It adds no model tool, prompt, route, worker action, role dispatch, approval, resource grant or policy default. A prepared record is an immutable intent, not dispatch, a running child or successful delivery. D81's original per-run kernel/lineage/cancellation work remains a separate prerequisite; these records do not manufacture a session or kernel identity.

`DelegationRecords` borrows the existing synchronous `DocumentStore`. Separate trusted `ParentAuthority` binds project, logical session, environment and original parent run. `HandbackAuthority` also binds the generated original delegation and child-run IDs. Constructing either DTO is not authentication; a future caller must derive it from authenticated control state. A historical plan/track/fingerprint, requested profile/model alias, reference or finite requested limit remains data. It grants no current plan-progress permission, installed configuration, resource access or enforced runtime budget.

`prepare` checks scoped exact operation replay before atomically generating one original delegation/child identity. `finish` records one terminal trusted host observation against that exact identity and expected prepared revision. It retains the child's original optional bytes and separately derives a strict structured handback. `get` exposes historical records plus the exact Python bytes; `list` pages a pinned parent-local event prefix, at most eight entries. An immutable mutation is also its event and historical receipt, binding action, operation ID, request hash, original scope/IDs and local sequence in one write transaction. The same operation with changed content conflicts; a terminal record cannot be overwritten or attached to another child. Replay returns the original receipt rather than new effects.

Trusted host ending (`returned`, `failed`, `cancelled`, `limit_reached` or `interrupted`) remains separate from the child's asserted `complete`, `partial` or `blocked` status. Structured summary, result pins, deviations and open questions are explicit fields of `sandbox-delegation-result-1`; they are claims, not verified science or host success. Unknown resolved models stay null. Original `None`, empty bytes, invalid UTF-8, invalid JSON and duplicate keys remain distinct. Invalid or over-budget derived data stays null with a fixed validation code, while the original bytes and host ending remain unchanged. No defaults, repair call, interpretation as instructions or scientific finding is supplied.

The default constructor does not initialize an absent namespace. Explicit trusted first setup is transactional, while partial/unsupported schemas refuse; concurrent first initializers observe one completed schema. Complete removal of every namespace table cannot be distinguished from never having initialized it without an external retained proof. Explicit initialization must therefore not be treated as automatic lost-history recovery. Logical session scope is not an opaque open-lifetime or current execution-eligibility proof.

Safety bounds are 64 KiB canonical brief, 64 KiB raw handback, 8 KiB canonical derived result, 96 KiB mutation metadata, 32 reference claims and 128 KiB complete event pages. Default retention is 256 delegations/64 MiB logical bytes per project and 1,024/256 MiB globally. These are storage bounds, not concurrency or spend defaults. Every immutable row's columns, raw bytes and fixed reservations count in the transaction; orphan or corrupt accounting refuses. There is no unresolved eviction or compaction. A terminal append may be refused at quota while its original intent remains unresolved. A caller must retain that uncertainty rather than infer failure, success or permission to repeat an effect. Logical charging does not measure SQLite pages/index allocation, RSS or arbitrary external database growth.

Copied host models and primitive/container subclasses are checked before overridable methods or aggregate encoding. SQL uses bounded type/byte projections before parsing, preserving an empty BLOB explicitly. Reads rederive structured data and verify recorded raw/derived/request/event identity. These checks detect incoherent retained state; they do not authenticate against an administrator rewriting the whole database. Arbitrary raw bytes define no HTTP representation and must not be implicitly decoded, executed or rendered as trusted markup.

The synchronous store owns no executor, asynchronous task or close method. Isolated tests show its owner's existing lock serializes close with an admitted write. This is not an async queue-drain guarantee. Any later adapter must retain actual admitted task/queue/SQL/borrowed-store ownership through timeout, repeated cancellation and shutdown. Records do not implement live model handback delivery, `RunRecord` save/ACK, restart reconciliation or unknown-effect recovery.
